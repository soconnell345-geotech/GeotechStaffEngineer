## The owner's standing rules

Each is binding. The long form is where the pointer says ("archive" = `module_work/history/CLAUDE_before_trim_2026-11-17.md`, by heading).

- **Review every model run in full** (2026-10-07). When results of any model run come back, read the full record of EVERY run, passing and failing, or have a capable helper read it and write it up; never judge from scores or tables alone. The record: `activity.jsonl` (every tool call with arguments and result, the model's own text), `run.json` / `messages.json` / `transcript.jsonl`, `FEEDBACK.md`, and the outputs themselves (open the PDFs, Word files and images). Reconstruct each run step by step and set a failing run beside a passing one of the same task; check every number it acted on against ground truth. Look for a model acting on what it was never shown, misleading tool results, wrong or gamed checks, prompts steering the wrong way, scorers measuring the wrong thing, and gaps in the record (then fix the logging). Write `TRACE_REVIEW.md` beside the results (`module_work/review_eval_results/<date>_<what>/`); raw traces in a gitignored `raw/` folder; every fix or follow-up goes into BACKLOG by id. Long form: archive, "REVIEW EVERY MODEL RUN IN FULL"; background `module_work/harness_theory/`.
- **One backlog file, stable ids** (2026-10-12). Every to-do, follow-up and owner question goes into `BACKLOG.md` with the next free id; no list in HANDOFF, a plan, a TRACE_REVIEW or a FINDINGS; an id is never reused. Ids from 900 up in each prefix are reserved for the maintainer's copy; a session here takes the next free id below 900. Long form: the top of `BACKLOG.md`; `webapp/tests/test_backlog.py` checks the ids.
- **No edge-case chasing** (2026-10-27). A follow-up becomes an item only if it changes a value in a saved report's output or what a live run returns; otherwise it is one "noted, not fixed" line in the parent's Done entry. Long form: BACKLOG, "How every session uses this file", item 2.
- **The notes checklist, after every item.** BACKLOG (the line moves to "Done since the last sweep" with the date and commit: `module_work/backlog_dashboard/close_item.py`); HANDOFF section 0a-current if the slice or a release changed; this file's state block if a version, tag or pin moved; the Backlog Desk rebuilt and republished after any BACKLOG change (`module_work/backlog_dashboard/build.py`, same URL); the session's own memory notes. Long form: BACKLOG, "How every session uses this file", items 3 and 4.
- **The repositories are public** (this one, planlens, geotech-references). Made-up values only in tests, fixtures and examples, never a value from a real project's documents; no names of clients, projects, posts, departments or people; no identifiers of a hosted platform (workspace, dataset or model ids, internal host names). The owner's documents live only under gitignored paths (`tinyapps/reference/`, `module_work/field_feedback/**/raw/`). Run `webapp/tests/test_public_text.py` before every commit (it reads `git ls-files`: `git add` a new file first); it catches only the words it guards, so read your diff too. planlens has no such test. Long form: `MAINTAINERS.md` section 5, "Made-up values in tests"; archive, "Environment".
- **Print only.** Every formula, coefficient, curve and default traces to a printed page (manual, edition, page, equation or table); no value from memory; a gap in the print is said, not filled. Long form: `MAINTAINERS.md` section 5; `module_work/cloud_briefs/COMMON_MODULES.md`.
- **Open methods.** Where references differ, offer each as a cited option and state the default and why; never one silent basis. Long form: `MAINTAINERS.md` section 5; `geotech_common/choices.py`.
- **Judgement stays with the agent, and is stated.** Modules stay general; what a run chose is in its `choices` and `defaults_used`, and the agent lists its judgement calls, each with its source or "no reference found". Long form: `MAINTAINERS.md` section 5; `funhouse_agent/judgment_check.py`.
- **The generated manual is never edited by hand.** Change `docs/user_manual/manual_content.py` or the tool's `METHOD_INFO`, then rebuild; `webapp/tests/test_user_manual_current.py` fails on a hand edit. Long form: `MAINTAINERS.md` section 5.
- **Figures.** No ink that carries no data; plans as drawings, to scale; elevation up a profile; kPa and kN; units and the coordinate system named. Long form: `MAINTAINERS.md` section 5; the checklist in `packages/aec-agent-core/aec_agent_core/deep/figure_helper.py`.
- **Framing and voice in user-facing text.** Geotechnical engineering is the practice of building on and in the ground; the ground is variable and partly known, so a single number is never the answer: analysis is repeated calculation across plausible subsurface and loading conditions against the design requirements, and the true answer is a distribution. The tools are not a replacement for judgement but a multiplier for it. Keep that voice ("practice", "on and in the ground", "design requirements", "subsurface and loading conditions") in `README.md`, `docs/overview.html` and every user-facing page. Long form: archive, "What this is for".
- **Gate on GitHub, not on this machine** (2026-11-11). Push the branch as `ci/<name>` (`git push origin HEAD:refs/heads/ci/<name>`): `tests.yml` runs all eight jobs; planlens' own `tests.yml` does the same for a `ci/<name>` branch there. Read the result from the public API (`.../actions/runs?branch=ci/<name>`); a failed job names its failed tests in the job's annotations, no sign-in needed (`.../check-runs/<job id>/annotations`, INF-81). Merge on green, then delete the remote branch. Run locally only the test files a change touches; judge every run by pytest's exit code, never through a pipe. A notes-only commit starts no run. Long form: archive, "Packages, pages and hosts"; `MAINTAINERS.md` section 4.
- **Releases are the owner's.** No version bump, tag or publish without the owner's explicit word, or a standing word for that kind of release; a pushed tag publishes at once, and the index never takes a version twice. Long form: `RELEASING.md`, its three facts; archive, "v5.3.0 status".
- **Paid-run outputs persist.** Every output of a paid or cluster run is written where it survives (the owner's workspace folder), never only to `/tmp` or DBFS (2026-09-20). Long form: archive, the 5.22.0 entry (`durable_dir`).
- **Secrets and the shared tree.** API keys come from the environment at run time, never through chat or a transcript; other sessions may share a checkout, so stage by exact path and check `git diff --cached` before committing. Long form: archive, "Gotchas the next team MUST know".
- **Code conventions** (all Python here): SI units (m, kPa, kN, kN/m, degrees); results as dataclasses with `.to_dict()` for the agent; no imports between analysis modules (`geotech_common` excepted). Long form: archive, "Architecture Patterns"; `MAINTAINERS.md` section 6.
- **Design decisions that stand** (one line each; long form in the archive): figures are found with text and read with pixels, no image embeddings ("HANDOFF — Figure Read-Off"); `foundry/` is not deleted before its importers are excised (BACKLOG INF-06, "Architecture Patterns"); reference-library builds ran milestone by milestone, without per-step asks ("Reference-Layer Build Work"; the library is now the maintainer's).

**The app's exact pin.** `webapp/tests/test_wheels.py` checks that the app's `aec-agent-core==` pin equals the version in `packages/aec-agent-core/pyproject.toml`, so a core version bump moves the app's pin in the same commit. `publish.yml` stops an app release while the pinned core is missing from PyPI or while `packages/aec-agent-core/` has changed since the pinned version's tag. The maintainer adopts each release as its wheel plus its source folder (`RELEASING.md` section 4).

**Fingerprints.** What a page's model is handed (system prompt, tool names, descriptions and schemas, helpers, middleware, budgets) is pinned as hashes. A change that moves them re-records in a commit of its own that says what moved and why; never hand-edit the files.

- A new planlens needs its own entry: the fingerprints keep one per planlens version, and for a version with no entry the test skips off CI and fails on CI. Install the new wheel, record, commit on its own (`RELEASING.md` section 4). Raise `planlens>=` only when the app needs the release.
- A planlens release turns CI red at once (CI takes planlens from PyPI): record the app's and Document Review's new entries the same hour it reaches PyPI (582f9a2 for 0.16.0). `record` also rewrites the app part, which comes out wrong in a worktree without the `geotech-references` submodule: record from a full checkout, or write only the planlens part (`RELEASING.md` section 4).
