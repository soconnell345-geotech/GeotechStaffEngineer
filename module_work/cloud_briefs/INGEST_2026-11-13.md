## 1. RI-103: every drawn line an interval, written changes as notes, stratum labels as printed

Branch `claude/ri-103-log-intervals`. CHECK at `module_work/ri103/CHECK.md`. BACKLOG RI-103, parts (1) and (2) only. Part (3), mapping intervals to the narrative's units, is a later model step: do not build it, but do not close the door on it (each interval must stay addressable so a later step can give it one unit or none).

All of it sits behind one switch, `GEOTECH_INGEST_LOG_INTERVALS`, off by default, on the model-first log path only. Today's log reader and the floor are not changed.

With the switch on:

1. **Intervals.** The log instruction and the log answer schema ask for every line the log draws across its soil column as an interval boundary: the depth, the elevation where the log prints one, the description as printed, the classification as printed. The builder never merges two intervals, whatever their descriptions: find every place the model-first path or the builder it reuses joins, drops or de-duplicates layers, and under the switch keep them apart (say in CHECK.md what you found).
2. **Notes.** A change the log writes inside an interval without drawing a line ("wet below 7 ft", "as above, but brown", "becoming gray at 3.5 ft") is a note on that interval: its depth where one is written, and its words as printed. It is not a new interval.
3. **Lines.** Where the log's legend or the line itself distinguishes kinds of line (solid, dashed, "approximate", "inferred", "gradational"), the interval keeps the kind of its top line as printed, and whether the line runs the full width of the column. Empty when the log says nothing: never guessed from the picture's look alone unless the legend defines it.
4. **Stratum labels.** A label goes on an interval only where the log prints one: a stratum or unit column, a geologic symbol or formation name, a model-layer number, a tag such as FILL or TILL set apart from the description. Kept as printed, with where it was printed (the column's heading, or "in the description"). A label that the log prints once and that plainly runs down over the intervals below it (a bracket, an arrow, a merged cell) is given to those intervals marked as carried; where the extent is not plain, only the interval it is printed against gets it.
5. **The record.** New optional fields on `Layer` (and on the reading class the model fills) for the notes, the line kind and the label with its source and its carried mark. Units and provenance as the rest of the layer has them: a note's depth is a `Quantity` in the log's unit with the page.
6. **Consumers.** The summary and page writers, the DIGGS writer, the library, the question list and the reconciler all read `layers`. With the switch off none of them changes. With it on, each must still work with more, shorter intervals and with the new fields present: run their tests with a switched-on record, fix what breaks, and list in CHECK.md what each does with the new fields (DIGGS: leave the new fields out of the file in this branch and say which DIGGS 2.6 element each would go to).
7. **The scorer and the answer sheets.** The lead will correct the private answer sheets to the same rule after your branch merges, so define and document what a sheet may now carry (`report_ingest/log_scoring.py`, and `module_work/report_ingest_harness/truth_records.py` where a sheet is turned into a record): an interval's notes, its line kind, its label, source and carried mark. Scoring: a sheet without the new keys scores exactly as today (pin it with a test); where a sheet has them, notes are scored by depth (the layer-top tolerance) and words (the scorer's existing description comparison), and labels as printed, exact after whitespace and case; a label the record carries down that the sheet marks as printed (or the reverse) is a miss on the carried mark, not on the label. Report them as groups of their own so today's totals stay comparable. Write the sheet format for the lead under "To measure live", with one made-up sheet.

Tests, all on made-up logs drawn with PyMuPDF or built as answers: a log with a line at every change of description (every interval kept, none merged, including two adjacent intervals with the same classification); a written change with a depth and one without; a stratum column; a label carried over three intervals and one whose extent is not plain; a legend that defines a dashed line; the three switch tests from the common list; one consumer test each for the summary writer and the DIGGS writer with the switch on.

The instruction's words are a judgement: say plainly what a drawn line is, what a written change is, and that neither is ever merged or promoted to the other, in the terms a log legend uses. Keep it short; the log instruction is already long.

## 2. RI-79: the log scorer's conventions for a paired public answer

Branch `claude/ri-79-scorer-conventions`. CHECK at `module_work/ri79/CHECK.md`. BACKLOG RI-79 ("merged from RI-85": its list is below, because the merged line dropped it).

1. **Comma-joined increments.** `log_scoring._blow_numbers` reads a blow record written as one string of increments ("3,6", "3, 6, 8", "3/6/8", "3-6-8") as its first number only. Read every increment. A string that is one count over a penetration is item 2, not this.
2. **A count over a penetration.** A refusal written "50/20" (blows over the penetration reached, here in millimetres; "50/5\"" in inches) has its penetration read as a blow count. Read the count as the count and keep the penetration out of the counts, in either unit; `model.SPT`'s docstring says how the record keeps such an entry.
3. **Blows on a driven tube sample.** The AGS4 answer carries a driven tube sample's blow count on the sample; the scorer credits blows only on drive records. Read how the record keeps a driven sampler that is not a split spoon (`model.SPT`, `model.Sample`, `SampleKind`), then make the answer sheet and the scorer agree with the record: a tube sample's blows are found when the record holds a drive record at that sample's depth with those blows. If the record has no place a model-first reading can put them, do not add one here: score the group as "no slot in the record" (counted, not a miss) and say so in CHECK.md.
4. **N from the increments.** The scorer's drives-to-N fallback, and the record's own check of a printed N against its drives, take the second and third of three increments. A record driven in six increments has a different rule, and the answer's N on such records is the sum of the last four. Find each rule in print: the reference library first (`geotech-references/`: search for the SPT procedure), then the AGS4 data dictionary's own definitions of its seating and test increments if a copy is held in the repository (do not fetch one). Then: (a) the fallback computes an N only for a count of increments whose rule you can cite, with the cite in the code; (b) for any other count it computes nothing, and an answer N with no printed N in the record is reported in a group of its own ("N not printed, no rule held for this number of increments"), not as a miss; (c) the record's own printed-N check is treated the same way if, and only if, it sits in scorer or QA code: if changing it would change a saved record's values, leave it and write it up under "Calls made". Never write a standard's rule from memory as if it were the print.
5. **Sample ids.** If sample ids are scored, the answer's id for an AGS4 sample is its type and its reference together, as a log prints them; built from one alone, nearly every id misses. Read `ags_truth.py` and the scorer's id comparison and make the converter build the id that way; keep the comparison's existing tolerance for spacing and punctuation.
6. **Header fields the form may not print.** The converter fills header fields from the AGS4 data whether or not the scanned form prints them. Add to the converter's sheet a list of header fields it took from the data (so a reviewer who may open the pages can strike the ones the form does not print), and have the scorer leave a struck field out of the total. Do not strike any yourself.
